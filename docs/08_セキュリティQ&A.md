# MaruDoc セキュリティ Q&A

2026-10-19 時点、ビルド 8。答えはすべて、この日に実物で確かめたことに基づく。確かめ方は各項目の末尾に書いた。

## 本当に通信しないのか

通信するコードがない。ソースに URLSession、Network、WebKit、ソケット系の API は1つもなく、リンクしているのは Apple 標準のフレームワーク (AppKit、PDFKit、ImageIO、Vision など) だけ。外部のライブラリは使っていない。

動かしても通信しない。変換エンジンの自己テスト 144 件を、カーネルのサンドボックスで通信を禁止した状態 (`sandbox-exec` の `deny network*`) で走らせて全部通った。起動中の本体と Finder 拡張が開いているネットワークの口は 0 だった (`lsof -i`)。文字認識も Apple の Vision を Mac の中で使っている。

言い切れないことが1つある。直接配布版の本体はサンドボックス化していないので、通信しないことを OS が強制しているわけではない (通信するコードがない、という状態)。App Store 版はサンドボックスで、通信の権限を持たないので OS が強制する。疑う人には LuLu や Little Snitch で監視してもらえばよい。

確かめ方: `lsof -nP -i -a -p $(pgrep -x MaruDoc)` が空であること。

## アクセシビリティの権限で何を見ているのか

デスクトップのアイコンを長押ししたことを知るために、マウスのボタンとドラッグのイベントを受け取っている。どのアイコンかは、Finder のアクセシビリティ情報からファイルの場所を読む。

キー入力は、長押しメニューを開いている間だけ受け取る (Esc で閉じるため)。メニューを閉じている間は、キーボードのイベントを受け取る仕組み自体を止めている。どのイベントも記録や保存はしない。ログに残るのは操作の種類と件数だけで、ファイル名や中身は残さない。

長押しメニューを使わない人は、設定で切ってアクセシビリティの許可を外せる。右クリックメニューは許可なしで動く。

## Finder の操作 (オートメーション) で何をしているのか

変換したファイルを、デスクトップ上で元のファイルの隣に置く。それだけに使う。Finder に送るスクリプトは固定の文で、ファイルの場所は引数として別に渡す。ファイル名に記号を仕込んで命令を差し込む攻撃は、この作りでは成立しない。ビルド 7 まではパスをスクリプトに埋め込んでいたので、公開前の点検で見つけて直した。

## 細工したファイルを開いたらどうなるか

自前の読み込み処理 (ZIP、Word/Excel/PowerPoint の XML、PDF の解析) は Swift で書いていて、メモリを壊す種類の不具合が起きにくい。そのうえで、細工したファイルで落ちたりメモリを使い切ったりしないよう、数値の範囲と大きさの上限を全部の箇所に入れた。

- XML の外部参照は無効にしてあり、DOCTYPE を含む Office の部品は読まない (別のファイルを読ませる攻撃を防ぐ)。
- HTML と Markdown の画像は、元のファイルと同じフォルダの中のものしか埋め込まない。
- 文書の中のリンクは http、https、mailto しか開かない。
- PDF と画像の描画は PDFKit と ImageIO で、プレビュー.app と同じ部品。

アプリには Hardened Runtime を有効にした署名をしてあり、JIT やライブラリ検証の無効化といった例外の権限は持っていない。外からコードを読み込ませる手口は OS が止める。

## ほかのアプリや Web ページから操作されないか

Finder 拡張と本体は `marudoc://` の URL でつながっている。本体は、自分の Finder 拡張からの要求だけを確認なしで実行する。拡張は App Group に置いた使い捨ての合言葉を付けて送り、合言葉は要求ごとに作り直す。拡張は、送り先が同じ開発者 (チーム ID) の署名をした MaruDoc 本体であることを確かめてから送る。

合言葉のない要求は、何をどのファイルに行うかをフルパスで見せる確認画面を出す。確認中に届いた要求は捨てる。開発用の経路はリリース版に入っていない。

## 配っているファイルは本物か

DMG と中のアプリは Developer ID (Yitao Ding, FC2V887B8C) で署名し、Apple の公証を受けて証明書を埋め込んである。

1行インストール (`curl -fsSL https://marudoc.app/install.sh | sh`) は次の順で確かめてから入れる。不一致があれば止まる。

1. DMG の SHA-256 をスクリプトに書いた値と照合する。
2. 署名、チーム ID、バンドル ID、公証を確認する。

サイトは HTTPS のみで、.app ドメインはブラウザが常に HTTPS で開く (HSTS プリロード)。サイトは外部のスクリプト、解析ツール、フォントを読み込んでいない。

確かめ方: `spctl -a -vv /Applications/MaruDoc.app` で source=Notarized Developer ID と出ること。

## データを集めていないか

集めていない。解析ツール、広告、アカウントはない。App Store のプライバシー表示も「データの収集なし」にしてある。設定は Mac の中にだけ保存する。

## 自動アップデートは

ない (通信しないため)。新しい版はサイトから入れ直す。セキュリティの修正を届けるには、利用者に入れ直してもらう必要がある。これは通信しない設計の代償。

## 第三者の監査は受けたか

人間の専門家による外部監査は受けていない。行ったのは次の3つ。

1. **複数エージェントの自動スキャン (claude-security):** 重大 0件、中程度 2件、軽度 30件。全件を修正した。
2. **修正後の読み取り再確認:** 別のセッションが2回行い、塞がったことを確かめた。
3. **公開前の自主点検:** スキャンが拾っていなかった2件 (Finder スクリプトへの埋め込み、キー入力の受け取り範囲) を見つけて直した。

## 編集の保存でファイルを壊さないか

保存は、元のファイルを控えてから新しい内容を書き、入れ替える。途中で失敗したら元に戻す。ファイルの権限も元のまま保つ。Word の保存は本文だけを書き直し、それ以外の部品はそのまま写す。

## 墨消しは本当に消えるのか

墨消ししたページは画像として描き直すので、下の文字は残らない。描き直しに失敗したページがあれば、保存自体を止める (消えていないまま保存されることはない)。

## 正直に言っておく弱いところ

- 直接配布版はサンドボックスなしで動く (通信しないことはコードの性質で、OS の強制ではない)。
- アクセシビリティは強い権限なので、MaruDoc 自体が乗っ取られたら悪用されうる。乗っ取りを防ぐ層は、Hardened Runtime、公証、メモリ安全な言語、入力の上限の4つ。
- 1行インストールは curl 経由なので、Gatekeeper の初回確認は出ない。代わりにスクリプトの中で同じ確認をしている。
- 自動アップデートがないので、古い版を使い続ける人が出る。
